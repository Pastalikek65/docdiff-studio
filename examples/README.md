# Synthetic acceptance corpus

This directory contains deterministic, authored PDFs for DocDiff Studio acceptance work. They contain fictional labels and numbers only. The corpus is generated by `generate.mjs` with `pdf-lib` 1.17.1, fixed PDF metadata dates, and uncompressed PDF object streams. `corpus/manifest.json` records each persisted file's SHA-256, size, purpose, and expected comparison behavior where that behavior is defined.

Regenerate from the repository root after dependencies are installed:

```powershell
node .\examples\generate.mjs
```

The corpus covers an exact identical pair, a word and number change, insertion of a middle page with stable anchors on both sides, a visual-only rectangle color change, an image-only scanned-page surrogate with no PDF text layer, a truncated malformed PDF, and valid resource-limit candidates for page count, extracted text, and aggregate rendered pixels. The image-only sample is synthetic; it is not OCR training data and makes no OCR claim.

These authored fixtures are licensed under the repository's Apache-2.0 license. `pdf-lib` is used only as a development-time generator dependency; its upstream license remains with the package and is not copied into the corpus. Rebuilding requires the pinned project dependency. If regeneration changes a fixture hash, review the PDF library/runtime change and update the manifest intentionally.

The plan's resource budgets are owned by the engine. The `resource-*` candidates intentionally record size/shape, not an expected error code, until acceptance coverage is tied to the shipped cap values. They include 201 pages, 2.05 million selectable characters distributed over 41 pages (50,000 per page), and a 110-page case whose aggregate raster area exceeds 80 million pixels without exceeding the page-count cap. A separate pair has 9000 by 9000 point pages to check that safe downscaling uses rendered dimensions rather than rejecting the page's physical dimensions. Two 10-page render workloads support worker-termination acceptance.
