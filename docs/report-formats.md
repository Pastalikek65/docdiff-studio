# Comparison and batch report formats

Reports contain document basenames, SHA-256 fingerprints, extracted text and, for PDFs, page images. They are copies of potentially private content. Source document bytes, local paths, OOXML part paths and OCR model data are excluded. Each JSON and HTML output is limited to 64 MiB in UTF-8. Report generation preflights both formats before signaling completion.

Schema 1 is the PDF-only API first published with v0.1.0: `compareDocuments`, `serializeReport`, and `renderHtmlReport`. Its page indexes and existing error meanings remain unchanged; the v1.0.0 upgrade acceptance exercised schema-1 JSON export and reopened its standalone HTML report. Schema 2 is the current stable API: `compareDocumentsV2`, `serializeReportV2`, and `renderHtmlReportV2`. It requires explicit, matching `pdf` or `docx` formats and schema version 2. Unknown versions and mixed formats produce an explicit error. Adding DOCX does not reinterpret schema-1 page numbers as paragraph indexes.

Schema-2 document records carry `format`, `unitKind` and `unitCount`. Only PDFs have `physicalPageCount`. Rows have tagged `beforeLocation`/`afterLocation` or null for an unmatched side. DOCX locations identify a logical main-body paragraph or table row; `index` is its global unit index, with `tableIndex` and `rowIndex` for table rows. DOCX comparison covers supported text and basic cell order, not layout, formatting, computed fields or complete Word document equivalence.

Table `cellChanges` use source-order cell indexes. A null `beforeCellIndex` means an added cell; a null `afterCellIndex` means a removed cell. That structural difference remains a change even for an empty cell with no added or removed text token, and when whitespace is ignored. The desktop and HTML reports label the present side and its position. These indexes do not imply content-based alignment of inserted middle columns.

Rows report text changes, PDF-only visual samples, source evidence and optional exact move IDs. `summary.moved` counts only unchanged text fingerprints that are unique in both entire documents and were not otherwise aligned. Ambiguous repeated text is not evidence of a move. A DOCX's omitted/unsupported text-bearing features make certainty incomplete; a matching incomplete comparison is uncertain. OCR-derived matches always remain uncertain, regardless of the engine's confidence score. Detected differences can coexist with incomplete certainty and review warnings.

A completed single-pair workspace exports a direct schema-2 comparison. Multiple pairs or a partial/failed batch export a schema-2 `reportKind: "batch"` envelope with one job record for every attempted/queued pair. Each job includes sanitized document names and one of `succeeded`, `failed`, `cancelled`, or `not-run`; only successful jobs carry a projected comparison result. Failed/cancelled jobs carry a safe error, and the envelope summarizes every status. Do not infer a successful job from an absent result. The desktop bounds the aggregate retained/exported report data at 64 MiB and stops later work if that budget is reached; this is not an OS process-memory ceiling.

HTML is self-contained, escaped, and script-free. It labels supported DOCX units and OCR uncertainty and uses bounded local embedded images. It does not resolve links or remote resources from source documents. Future report consumers should explicitly check schema version and report kind before interpreting rows.
