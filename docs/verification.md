The local positive trial had tracked source changes and predated the final commit; it was harness/runtime evidence, not exact stable release qualification. The report-retaining follow-up [CI 37883334400](https://github.com/Pastalikek65/docdiff-studio/actions/runs/37883334400) passed Windows but failed the Linux source flow at keyboard focus timing. Its selected change had updated before the scheduled animation-frame focus callback ran. A separate actual-browser regression reproduced that ordering; the desktop harness was changed to wait for focus with a three-second bound and retain strict assertions in both navigation directions. This historical run did not qualify a release. The captured table also exposed a UI counter that counted all compared cells; its correction has a regression test. Fresh source and packages were required after those fixes and were later qualified in the stable run above.

Actual supported DOCX inputs also reproduced a false unchanged row when a trailing empty cell was added or removed with whitespace ignored. The engine now treats a cell index present on only one side as a structural change, preserving the report schema's empty text representation. Independent regression checks cover both directions through comparison, JSON and HTML; the UI and HTML label empty structural cells explicitly.

After these corrections, the Windows integration passed all 89 tests across 18 files, typecheck/build and the actual 23-step desktop flow. The examples were refreshed from that run. This local source run predates the next frozen commit and is not exact release-package qualification.
